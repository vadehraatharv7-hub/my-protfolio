## Why I built this

I want to understand how attacks look from the defender's side. That needs one place where events from many machines are collected, checked against rules and searchable, which is what a security operations centre does. I wanted a small one of my own, rebuildable from code and safe enough not to become the most attractive target in my lab. The story is in [A lab you can't see into teaches you nothing](/blog/wazuh-siem-unprivileged-lxc-terraform/).

## What it is

The monitoring core of my homelab. [Wazuh](https://wazuh.com/) collects logs and security events from agents on my machines, runs them through detection rules and shows the results in a dashboard. Here it runs as one unprivileged Debian 12 container (4 cores, 6 GB RAM, 50 GB disk) built entirely by Terraform.

```text
you    ─▶ security.atharvvadehra.dev ─▶ Cloudflare Access (one-time PIN) ─▶ tunnel ─▶ https://127.0.0.1:443 (dashboard)
agents ─▶ 192.168.50.52:1514 (events) / :1515 (enrolment)   only from the addresses in agent_sources
```

## How it is built

| File | What it does |
|---|---|
| `lxc.tf` | The unprivileged container with a static IP and key-only SSH |
| `firewall.tf` | The hypervisor firewall file for the container |
| `cloudflare.tf` | Tunnel, DNS record and Access policy listing who may sign in |
| `app.tf` | Runs the Wazuh installer (`wazuh-install.sh -a`) and `cloudflared` over SSH |
| `manager.tf` | Creates the agent groups and their configuration |
| `rules.tf` | Installs the custom detection rules |
| `shipper.tf` | Optional: copies every event into MongoDB (see the [log store](/projects/mongodb-log-store/)) |

The first apply takes 10 to 20 minutes, almost all of it the Wazuh installer.

## Two logins

Anyone on the guest list passes Cloudflare Access with an email PIN, and then signs in to Wazuh itself as `admin`. The Wazuh password is generated by the installer and stays on the container rather than in Terraform state; a Terraform output prints the command that retrieves it.

## Network containment

Wazuh holds logs from every monitored machine, so it gets the same containment as the decoys. The Proxmox firewall runs outside the container with policy drop both ways:

- **In:** SSH and the dashboard from the Proxmox host only. Ports 1514 and 1515 only from the addresses listed in `agent_sources`. Without that list, nothing can enrol.
- **Out:** DNS, NTP, the MongoDB log store (opened *before* the private-range drops, because the store lives on the same bridge), then web and the Cloudflare tunnel port to the public internet only.

## Decoys versus real machines

Wazuh is told what each machine *is* by the agent group it was enrolled in:

| Group | Meaning | Labels on every event | Other |
|---|---|---|---|
| `honeypots` | Intentional decoys | `decoy=true`, `origin=honeypot` | Hardening benchmark (SCA) and rootcheck switched off, because they would score a decoy against a policy it is not meant to meet |
| `internet-hosts` | Real machines I run on the internet | `decoy=false`, `origin=production` | |

A machine is therefore classified by *where I enrolled it*, never by guessing. Group files are validated with `verify-agent-conf` before use. Real machines join with `WAZUH_AGENT_GROUP=internet-hosts` at install time.

## Custom detection rules

`files/honeypot_rules.xml` uses the reserved rule IDs 100100 to 199 for the honeypots (details on the [honeypot page](/projects/homelab-honeypots-lxc/)). Installation is defensive: the file is copied in, checked with `wazuh-analysisd -t`, and **removed again if it does not load**, so a typo can never leave the manager down. Only then does the manager restart.

## Operational notes

- **Sizing.** Wazuh's minimum is 4 GB RAM; 6 GB leaves room for a handful of agents.
- **Host prerequisite.** The indexer needs `vm.max_map_count >= 262144`, a host-wide kernel setting that a container cannot change. The script stops with a clear message if the Proxmox host is too low.
- **Versions.** The three Wazuh packages are put on `apt-mark hold` so unattended upgrades cannot split them; upgrades are deliberate.
- **Failed installs** can be removed with `wazuh-install.sh -u` and re-applied with `terraform apply -replace=null_resource.app`.
- **TLS.** Wazuh's self-generated certificate is used over loopback with verification off; Cloudflare terminates the public TLS.
